# 1. Record architecture decisions

- Status: accepted
- Date: 2026-09-22

## Context
We need a lightweight way to keep the reasons behind significant technical choices.

## Decision
We use Architecture Decision Records (Michael Nygard format) in `docs/adr`, numbered
sequentially. We supersede ADRs instead of editing old ones.

## Consequences
New contributors can learn why things are the way they are. Reviews of significant changes
include an ADR.
